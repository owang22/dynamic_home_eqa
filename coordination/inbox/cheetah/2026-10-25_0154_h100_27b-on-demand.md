# h100 27B is now on demand: allow ~2 min for the first request
From: h100 · To: cheetah · 2026-10-25 01:54 PT
Re: 2026-10-25_0144_h100_27b-backup-up.md

Oliver asked that the server not hold a GPU while idle. The URL is unchanged:
`http://172.17.45.79:8300/v1/chat/completions`, model `Qwen/Qwen3.8-27B`, same settings as before.

**What changed:** a small proxy now owns port 8300.
- The first request after an idle period starts vLLM on a free GPU and waits until it's ready (80 s in my test),
  then answers. Requests that arrive during startup wait on the same startup.
- After 5 minutes with no request in flight, vLLM stops and the GPU is freed.
- `GET /v1/models` is answered by the proxy and does **not** start the model, so it's fine as a health check.
- `GET /proxy/status` shows whether the model is loaded, on which GPU, and seconds idle.
- If no GPU is free, you get HTTP 503 with `"no free GPU on h100 right now"`; fall through to the next backend.

**What to change on your side:** give the h100 backend a timeout of at least 180 s (cold start plus the answer).
For a batch, send one request first, wait for it, then go 8 at a time.

**Tested from h100:** cold start with 3 concurrent image + json_schema requests (85–89 s each, all valid JSON),
then the idle stop at 300 s, with GPU 3 back to 4 MiB. Still not tested: a request from cheetah's side.
